# Умный кредитный кабинет предпринимателя

Единый цифровой кредитный конвейер для МСП: **клиент** описывает задачу своими словами → ИИ-ассистент подбирает продукт и показывает «предодобрено до X ₽» → заявка → автоматические проверки (ЕГРЮЛ/ФНС/БКИ — симуляторы) → CatBoost-скоринг PD → кредитная политика и цена → оферта / контр-оферта / запрос данных / ручной разбор / отказ → онлайн-подписание → выдача. **Банк** видит очередь, PD, рейтинг A–E, SHAP-причины, трассу решения и принимает решение андеррайтера. Всё внутри веб-продукта (без почты, SMS и мессенджеров).

## Запуск
```bash
docker compose up --build        # http://localhost:8000 · Swagger /docs · OpenAPI /openapi.json
# локальная LLM (необязательно): LLM_BASE_URL=http://llm:11434/v1 docker compose --profile llm up --build
```
Без Docker: `cd backend && pip install -r requirements.txt && uvicorn app.main:app` · Тесты: `cd backend && pytest -q` · Переобучение модели: `python -m credit_ds.train`.
Переменные: `DB_PATH`, `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` (любой OpenAI-совместимый API; пусто = правила без LLM), `LLM_TIMEOUT`, `DS_KEY_RATE` (ключевая ставка, по умолчанию 0.14), `DS_ARTIFACTS`, `SIGN_SALT`. LLM запускается отдельно, в Docker её класть не обязательно.

## Учётные записи (синтетика)
`client1` — надёжный клиент · `client2` — серая зона · `client3` — высокая долговая нагрузка (пароль `client`) · `operator` / `operator` (лимит полномочий 3 млн ₽) · `senior` / `senior` (50 млн ₽). Демо-ИНН: 7700000001…06 (список в мастере заявки).

## Сценарий проверки (5 минут)
1. Войти как **client1**. На главной напишите «Купить печь для пекарни, 2,5 млн на 3 года» → «Что мы поняли» + продукты с лимитами.
2. «Оформить» → проверить данные → «Отправить заявку»: анимация конвейера → предложение с платежом и переплатой, причины решения.
3. Принять условия → «Подписать» → ввести код подтверждения (симуляция ЭП) → «Деньги выданы». Лента «Для вас» на главной изменилась по стадии (поле «почему вы это видите»).
4. Новая заявка без маржи → **Нужны данные** → ввести → пересчёт. ИНН 7700000004 → отказ (ликвидация, knock-out).
5. Войти как **operator** (в другой вкладке): очередь, KPI, карточка заявки (PD, SHAP, трасса, внешние данные), решение андеррайтера; у клиента статус обновится сам (опрос раз в 4 с). Вкладка «Модель риска» — метрики.

## Что делает его похожим на реальный продукт
Идемпотентная подача заявки, оптимистичная блокировка переходов, срок действия оферты, график платежей, центр уведомлений, автосохранение черновика; у банка — SLA, назначение исполнителя, лимиты полномочий и эскалация, воронка, поиск и фильтры очереди, экспорт CSV; эксплуатация — миграции БД, health/ready, Prometheus-метрики, JSON-логи, CI. Подробно и честно о том, что осталось до продакшена: `docs/PRODUCTION_READINESS.md`.

## Продакшн-контур
Два режима: **демо** (`docker compose up --build`, SQLite, демо-пользователи — для проверки жюри) и **продакшн** (`docker-compose.prod.yml`): nginx с TLS и лимитами запросов → приложение (non-root, read-only FS, без capabilities) → PostgreSQL с пулом соединений. Демо-пользователи и дефолтные секреты в продакшн-режиме запрещены (приложение не стартует). Пользователей создаёт администратор: `docker compose -f docker-compose.prod.yml exec app python -m app.manage create-user --login ... --role operator --name ... --limit 3000000`. Резервные копии — `deploy/backup.sh`. Подробности и честный список оставшегося — `docs/PRODUCTION_READINESS.md`.

## Обучение модели (v2)
`make train` (= `python -m credit_ds.train --n 150000 --trials 12`): хронологическое разбиение, подбор гиперпараметров random search с expanding-window CV по времени, сравнение с логрегрессией, Platt против изотоники, бутстреп-интервалы, срезы по отрасли/форме/региону, стабильность по кварталам, PSI признаков, **ворота выпуска** (модель попадает в `artifacts/` только при прохождении порогов, иначе — в `artifacts/candidate/`), реестр версии (хеши данных и артефактов, версии библиотек). Всё отображается в кабинете банка на вкладке «Модель риска». Поставляемые в архиве артефакты — прежняя модель; чтобы получить новую, запустите `make train`.

## Архитектура
См. `docs/states.md` (состояния, ER, схема), `docs/README_DS.md` (DS-часть подробно), OpenAPI — `/docs`, запросы — `docs/requests.http`.
- `backend/app` — API, аутентификация (токены 12 ч, лимит попыток входа), **конечный автомат с проверкой переходов (409)**, аудит-лог событий, ролевой доступ (клиент не видит чужие заявки, PD и трассу), `engine.py` — адаптер к DS.
- `backend/credit_ds` — DS-модуль: intent (правила + опц. LLM), рекомендации, PD (CatBoost + монотонность + калибровка), решение, цена, объяснение, лента, мониторинг PSI. Доступен и как `/ds/*` (только с токеном).
- `backend/app/static` — SPA без зависимостей (светлая/тёмная тема, клавиатурная навигация, адаптивно).

## MVP: что вошло и почему
Все стадии пути от потребности до выдачи, две роли, пять исходов решения. Подпись и выдача — симуляция; документы, залоговая оценка и реальные интеграции не вошли.
## Ограничения и развитие
SQLite → PostgreSQL + миграции; JWT/SSO и RBAC-политики; асинхронный пайплайн (очередь) и идемпотентность; метрики модели синтетические (см. честную оговорку в `docs/README_DS.md`); reject inference, champion/challenger, ретрейн по PSI; OCR документов; fairness-аудит.
