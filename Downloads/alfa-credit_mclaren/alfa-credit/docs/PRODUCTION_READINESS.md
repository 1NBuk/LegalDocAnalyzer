# Готовность к промышленной эксплуатации
Честная карта: что уже сделано в прототипе и что нужно для продакшена.

| Область | Сделано | Следующий шаг |
|---|---|---|
| **Безопасность** | PBKDF2 с солью на пользователя; в БД хранится только хеш токена сессии; TTL 12 ч, logout; блокировка перебора; ролевой доступ (клиент / андеррайтер / старший); заголовки CSP, X-Frame-Options, nosniff; валидация входа (Pydantic); экранирование вывода в UI; PD и трасса скрыты от клиента | SSO банка/OIDC, MFA, секреты из Vault, rate-limit на шлюзе, WAF, шифрование ПДн, DAST/SAST в CI |
| **Корректность** | Конечный автомат с проверкой переходов; оптимистичная блокировка и атомарная транзакция «статус + событие»; идемпотентность создания заявки (`Idempotency-Key` + уникальный индекс); срок оферты (EXPIRED) | Саги/outbox для реальных платежей, повторные попытки интеграций с backoff и circuit breaker |
| **Бизнес-процесс** | SLA андеррайтера, назначение исполнителя, лимиты полномочий и эскалация (принцип «четырёх глаз»), аудит-журнал каждого действия, уведомления в продукте | Очереди по компетенциям, авто-распределение, отчёты по SLA |
| **Данные** | PostgreSQL с пулом соединений (`DATABASE_URL`), версионируемые миграции под advisory-lock (безопасно при нескольких репликах), индексы, скрипт бэкапа/восстановления, SQLite только для демо | Alembic, партиционирование событий, шифрование ПДн, политика хранения и удаления, PITR |
| **Наблюдаемость** | Структурные JSON-логи с request-id, `/api/health`, `/api/ready`, Prometheus-метрики `/api/metrics` (запросы, задержки, заявки по статусам) | Трейсинг (OpenTelemetry), алерты по SLO, дашборды |
| **ML-риск** | CatBoost + калибровка, монотонные ограничения, SHAP-причины, политика отдельно от скоринга, мониторинг PSI; обучение v2: CV по времени, подбор гиперпараметров, бутстреп-ИИ, срезы, ворота выпуска, реестр версий | Валидация на реальных данных, champion/challenger, модельный риск-комитет, fairness-аудит |
| **Качество** | pytest (e2e по API + тесты DS), GitHub Actions: тесты + сборка образа | Контрактные тесты, нагрузочные (k6), e2e UI (Playwright) |
| **Инфраструктура** | Контейнер non-root, read-only FS, `cap_drop: ALL`, лимиты ресурсов, healthcheck; nginx: TLS 1.2+, HSTS, rate-limit логина и API, метрики и `/ds` только из внутренних сетей, Swagger отключён в проде; запуск без секретов и с демо-пользователями невозможен; троттлинг входа в БД (работает на нескольких репликах) | Kubernetes/оркестратор, секреты в Vault, WAF, сканирование образов, SBOM |
| **Масштабирование** | Приложение без состояния (кроме БД) — горизонтально масштабируется за балансировщиком | PostgreSQL, выделенный сервис скоринга, очередь для асинхронного конвейера, Redis для rate-limit |

## Целевые показатели (ориентир, не SLA)
Оценка заявки < 1 с (CPU), p95 API < 500 мс без скоринга, доступность 99,5 %, рассмотрение андеррайтером ≤ 4 ч (`SLA_HOURS`).
## Известные ограничения прототипа
SQLite (один узел), счётчики попыток входа и метрики в памяти процесса, подпись и выдача симулируются, внешние сервисы — моки, модель обучена на синтетике.

## Что нельзя закрыть кодом
Валидация модели на реальных данных и модельным комитетом; пентест и ИБ-аудит; соответствие 152-ФЗ и требованиям ЦБ; интеграция с реальными ЕГРЮЛ/ФНС/БКИ и подписью; SSO банка; нагрузочное тестирование на целевом оборудовании. Prometheus: `scrape /api/metrics` (пример: `static_configs: [{targets: ['app:8000']}], metrics_path: /api/metrics`).
